2026-10-26 RAG 샘플용 환경을 추가했다. `.runtime/venv-rag`에 Qdrant client 1.20.0·lxml 6.1.3·httpx 0.28.1·tokenizers 0.23.3을 설치했고 `pip check`를 통과했다. 기존 비전/Paddle 환경은 유지했다. 임베딩은 기존 Ollama의 `qwen3-embedding:0.6b` Q8_0를 사용하며 배치 4·문맥 2,048, 실제 1,024차원 벡터를 생성했다. 646개 청크 실행 중 GPU 메모리 관찰 최대 1,016MiB, 온도 59°C였다. [실행 안내](RAG_PIPELINE.md), [측정 보고서](reports/RAG_SAMPLE_20261026.md). 아래는 기존 그림 설명 환경의 이력이다.

## Ollama 서버

기존 프로젝트용 portable Ollama 0.40.4를 재사용한다. 시스템 전역 설치나 드라이버 변경은 하지 않는다. Ollama 시작 로그에서 CUDA와 RTX 5060 Laptop GPU 인식을 확인했다. 이는 모델을 GPU에 적재해 추론한 결과와는 다르다.

| 설정 | 값 |
|---|---|
| 실행 파일 | `.runtime/ollama/ollama.exe` |
| 모델 저장소 | `.runtime/models` |
| 서버 주소 | `http://127.0.0.1:11434` |
| 동시 요청 | 1 |
| 동시 적재 모델 | 1 |
| 기본 컨텍스트 | 4,096토큰 |
| 클라우드 기능 | 비활성화 |
| 서버 로그 | `.runtime/pm209-11434.stdout.log`, `.stderr.log` |

명령의 작업 위치는 저장소 루트 `rag_activity`다.

```powershell
# 서버 시작만 수행한다. 모델 추론은 시작하지 않는다.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File PM209/scripts/start-ollama.ps1

# 모델 다운로드와 이미지 입력 지원 여부만 확인한다. 추론하지 않는다.
.\.venv\Scripts\python.exe -X utf8 -B PM209/scripts/prepare_model.py
```

기존 서버가 같은 주소에서 실행 중이면 시작 스크립트는 그 서버를 재사용한다. 이때 기존 서버의 설정을 변경하지 않으므로 실행 로그와 설정을 확인해야 한다.

## 사용할 모델

그림 설명 생성에는 `qwen3.5:4b`를 사용한다. 2026-10-21 다운로드와 Ollama SHA-256 검증을 완료했다. 모델은 Q4_K_M 양자화이며 이미지 입력 구성요소를 포함한 크기는 3,324,173,934바이트, 약 3.1GiB다. 디스크 크기는 실제 추론 VRAM 사용량과 다르다.

모델 메타데이터에서 `vision` 지원을 확인했다. 준비 완료 직후 `/api/ps`의 적재 모델 목록은 비어 있었으며 모델 추론은 실행하지 않았다.

다운로드 완료 여부, 모델 digest·양자화·이미지 입력 지원 여부와 메모리 적재 상태는 준비 스크립트가 `.runtime/pm209_environment.json`에 기록한다. 이 기록은 모델 추론 결과가 아니다.

## 추론을 시작할 때의 설정

현재 설명 생성 코드의 기본값은 그림 1개씩, 이미지 긴 변 최대 1,536픽셀, 컨텍스트 4,096토큰, 출력 최대 768토큰, temperature 0, 추론 모드 끄기다. GPU 자동 적재를 요청하며 첫 실제 생성 후 GPU 적재 여부를 확인한다. 표본 실행에서 장치 전체 GPU 메모리 사용량은 관찰 최대 3,828MiB, 온도는 최대 68도였다. 이는 장시간 전량 실행의 실측이 아니다.

2026-10-22부터 새 출력은 영어 2~4문장, 최대 100단어를 목표로 간결하게 요청한다. 길이·형식 오류에 한해 최대 세 번 시도하며, 재시도는 두 문장에 최대 60단어·40단어로 줄인다. GPU·컨텍스트·출력 토큰 상한은 늘리지 않았다. 세 번 실패한 그림은 전체 실행기에서 기록 후 뒤로 미루고, 모든 다른 그림 처리 후 한 번 더 확인한다. 상세한 완료·미완료 상태는 README의 실행 설명을 따른다.

같은 날 `token repeat limit reached`를 응답 생성 중 예외로 받는 경로도 재시도 대상에 추가했다. 메모리 부족·모델 누락·일반 서버 오류는 이 예외와 구분한다. 재개 시 기존 모델·VRAM·컨텍스트 설정은 그대로 사용한다.

전체 실행기는 `scripts/run_full.py`이며 100개마다 정상 보강본을 저장한다. 원본 전체와 대조하여 페이지·영역·QA 보존을 확인하고 이어서 처리한다. GPU 상태는 약 5초마다 기록한다. Windows 자동 유휴 절전은 실행기 수명 동안만 방지한다. 청킹·임베딩·Qdrant 설치는 후속 작업이다.
