# PM209 질문 범위에 집중하는 프롬프트 비교

2026-11-08

부모 문맥을 연결한 이전 답변을 기준으로, 시스템 프롬프트만 수정해 같은 30문항에 키워드 0%·50%의 답변 60개를 생성했습니다.

| 키워드 비중 | 이전 프롬프트 | 새 프롬프트 | 차이 |
|---|---:|---:|---:|
| 0% | 73.3% | 70.0% | -3.3%p |
| 50% | 66.7% | 63.3% | -3.3%p |

| 키워드 비중 | 본문: 이전 → 이후 | 표: 이전 → 이후 | 그림: 이전 → 이후 |
|---|---:|---:|---:|
| 0% | 90.0% → 90.0% | 80.0% → 80.0% | 50.0% → 40.0% |
| 50% | 80.0% → 90.0% | 70.0% → 50.0% | 50.0% → 50.0% |

전체는 비중별 30문항, 유형별로는 각 10문항의 완전 정답률입니다. 부분정답·미답변·출력 오류를 분모에 포함했습니다. %p는 반올림 전 비율로 계산했습니다.

## 바꾼 내용

- 질문한 사실·동작을 먼저 답하고, 질문하지 않은 사양·배경·예시를 덧붙이지 않도록 했습니다.
- 간결하게 답하되 필수 조건과 요청한 절차는 생략하지 않도록 했습니다.
- 표의 제목과 셀을 함께 읽고 수치·단위·범위·기술 용어의 의미를 유지하도록 했습니다.
- 대안(or)과 순서(then), 필수와 권장을 구분하고 근거에서 확인되지 않는 아이콘·위치 관계를 만들지 않도록 했습니다.
- 답변 전 근거와 누락 조건을 확인하되 내부 검토나 품질 플래그를 사용자에게 출력하지 않도록 했습니다.

실험 프롬프트 버전은 `pm209-focused-ko-v2`입니다. [이전 전문](prompt-before.txt)과 [수정 전문](prompt-after.txt)을 비교할 수 있습니다. 특정 평가 질문이나 정답 예시는 프롬프트에 넣지 않았습니다. **일반 CLI 실행은 기존 v1을 기본으로 유지**하며 `--answer-prompt focused`를 붙이면 이번 수정안을 선택합니다. `--answer-prompt baseline`은 기존 프롬프트를 명시적으로 선택합니다.

## 고정한 조건

- 기존 문서·질문 임베딩, Qdrant, 영어 번역, 검색 Top-5를 재사용했습니다.
- 부모 문맥까지 확장한 근거의 내용·개수·순서·source_id를 60개 모두 이전과 동일하게 유지했습니다. 문맥을 다시 검색하거나 잘라내지 않았습니다.
- 모델 Qwen3.5:4b, temperature=0, think=false, 문맥 8,192토큰, 출력 1,024토큰, 요청 제한 300초를 유지했습니다.
- 기존 JSON 검증·근거 인용·재시도 처리도 동일합니다. 코드 비교에서 프롬프트 상수 외의 답변 구현이 유지됐는지 확인했습니다.
- 이전 정답·검수 기준을 그대로 적용했습니다. 충분한 근거가 있는지의 판정도 입력이 동일하므로 이전 값을 유지했습니다.
- 같은 문항으로 프롬프트를 개선하고 제가 검수한 결과입니다. 독립된 새 질문 평가, 여러 번 생성한 변동성 검증, 원본 이미지를 직접 입력하는 실험은 별도입니다.

## 실행과 검증

- 60개 답변 생성·보존 확인: 1.9분. 출력 오류: 0개.
- GPU 관측 최대: 3836MiB, 72°C.
- 임베딩 생성 0회, 인덱스 쓰기 0회. 원본·보강본·기존 실험 결과 등 412개 보호 파일의 해시가 유지됐습니다.
- 관련 기존 테스트 22개와 프롬프트 선택·문맥 예산 검사 2개를 통과했습니다. 실행·형식 검증과 의미 정확도는 별도로 평가했습니다. 정답률은 기존 핵심 답변과 중요한 부가 오류 기준이며 문장별 인용의 완전성을 인증하는 지표는 아닙니다.

## 문항별 변화와 판단

이번 수정안은 **답변을 짧게 만드는 효과는 있었지만 전체 정답률 개선을 확인하지 못했습니다.** 두 키워드 비중 모두 이전보다 한 문항씩 낮았습니다. 30문항·1회 생성의 차이이므로 일반적인 우열로 확대하지 않고, 일반 실행의 기본 프롬프트는 이전 버전을 유지했습니다.

| 키워드 비중 | 평균 답변 길이: 이전 → 이후 | 정답으로 개선된 문항 | 정답에서 내려간 문항 |
|---|---:|---|---|
| 0% | 118.5자 → 104.5자 | 로밍 아이콘(TABLE09), 드릴 중심 맞추기(FIG01) | 점멸 횟수(TABLE08), 암호 분실(FIG06), 설치 절차(FIG07) |
| 50% | 123.5자 → 100.2자 | 입력 전압(TEXT08) | 소프트웨어 삭제(TABLE04), 로밍 아이콘(TABLE09) |

- **개선:** 50%의 입력 전압 답변에서 돌입 전류를 일반 최대 전류처럼 잘못 덧붙이는 설명이 없어졌습니다. 0%의 드릴 답변에는 빠져 있던 중심 맞추기가 포함됐습니다. 단, 해당 문장의 근거 S3를 인용 목록에서 빠뜨린 문제는 남았습니다.
- **새 오류:** 0%의 암호 분실 답변이 공장 초기화를 ‘모든 사용자 데이터 복구’ 방법처럼 설명했습니다. 원본은 초기화하면 사용자 데이터가 삭제된다고 명시합니다. 이 문항은 부분정답으로 내려갔습니다.
- **누락:** 0%의 설치 절차에서 재시작 권장을 생략했습니다. 50%의 리모컨 답변은 배터리 장착 확인을 계속 빠뜨렸습니다.
- **조건 혼합:** 50%의 소프트웨어 삭제 답변은 서로 다른 설치 파일에 해당하는 제어판 삭제와 수동 삭제를 합쳤습니다. ‘표의 조건을 보존하라’는 지시만으로 해결되지 않았습니다.
- **남은 한계:** 0%의 바구니 답변에는 중국어가 섞였고, 입력 전압·스토리지 등 일부 답변은 요청하지 않은 부연을 계속했습니다. 프롬프트 지시가 항상 준수되는 것은 아니었습니다.
- **채점상 주의:** TABLE07의 50% 답변은 충전 필요/충전 중 색상을 올바르게 구분했으나 잔량 표시 기능을 명확히 말하지 않아 부분정답으로 유지했습니다. TEXT06의 질문과 공식 정답 범위 불일치, FIG10의 원본 그림 기반 확장 기준도 이전과 동일하게 적용했습니다.

다음 개선은 모델에 전달할 근거에서 질문에 해당하는 표의 행·조건을 선별하거나, 답변의 수치·필수 조건을 근거와 대조하는 단계를 별도 실험하는 방향이 적절합니다. 이번 작업에서는 프롬프트 외 요소를 바꾸지 않았습니다.
