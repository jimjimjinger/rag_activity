## 검색 결과와 한계

영어 QA 126문항 모두 근거 ID를 해석할 수 있었다. 질문은 **검색 평가 때만** 임베딩했고 청크/DB에는 질문·정답·정답 근거를 넣지 않았다. 각 매뉴얼의 모든 청크를 조회한 후 페이지별 최고 유사도로 순위를 정했다.

| 지표 | 결과 |
| --- | ---: |
| 상위 1개 페이지 근거 적중 | 83/126, 65.9% |
| 상위 3개 페이지 근거 적중 | 112/126, 88.9% |
| 상위 5개 페이지 근거 적중 | 118/126, 93.7% |
| 상위 5개 청크의 직접 근거 영역 재현율, 질문별 평균 | 40.2% |
| 상위 5개 청크의 직접 근거 영역 정밀도, 질문별 평균 | 21.5% |

이 표본은 train의 3개 매뉴얼을 사용한 개발 확인이다. 전체 PM209 성능이나 test 성능으로 보고하면 안 된다. 페이지 적중은 정답 답변 생성 성공률이 아니다. 영역 지표에는 반복 제목과 중복 제거 연결 ID를 제외했으며, 부분 영역 청크가 검색되어도 해당 영역 ID가 맞으면 집계되는 한계가 있다.

별도로 한국어 질문 3개를 확인했다.

| 질문 | 실제 결과 |
| --- | --- |
| 스피커 강제 재시작 시간 | 9초가 들어 있는 표가 2위. 1위는 5초 공장 초기화로, 구별이 필요하다. |
| 노트북 무게와 크기 | 해당 페이지 제목 1위, 수치가 들어 있는 표 3위. 터치패드 크기가 2위에 섞였다. |
| 두 살 아이의 헤드폰 사용 | 상위 5개 청크에서 해당 경고를 찾지 못했다. |

따라서 **현재 파이프라인은 동작하지만 한국어 질문 검색을 충분히 잘한다고 판단할 단계는 아니다.** 다음에는 같은 청크를 유지하고 한국어→영어 검색 질의 변환, 제목 단독 청크 처리, 재순위화를 train/val에서 비교할 수 있다. 이번에는 검색 품질을 맞추려고 QA 정답을 프롬프트나 본문에 추가하지 않았다.

## 원본 이미지와 비교한 3페이지

- **Sound Joy 첫 페이지:** 원본 버튼 표의 9s·1s와 배터리 확인 조건이 청크에 남았다. 기존 HTML의 `holdfor` 같은 OCR 붙어 쓰기는 그대로다. 그림 설명과 표는 분리되어 있으며 표의 확인되지 않은 헤더에 표시를 붙였다.
- **Alienware 사양 페이지:** 29.99mm·424mm·332mm·4.42kg 등 현재 표에 저장된 수치를 유지했다. 원본에는 닫는 괄호가 있지만 기존 HTML의 `Windows 10 Professional (64-bit`는 빠져 있다. 청킹 과정에서 추측해 고치지 않았다. 제목 연결 일부는 보수적으로 생략됐다.
- **Bose 안전 안내 페이지:** 좌우 열을 섞지 않았다. 유해물질 표 HTML에는 병합 열 수가 7/8로 불일치한다. 셀 글자와 행 순서를 유지하고 열 대응을 확정하지 않는 방식으로 표시했다. 원본에서 잘못 추출된 `Hg` 등의 표기는 별도 OCR 보완 대상이다.

샘플에서 구조 불일치 표는 3개이며 8개 청크에 `table_structure_unresolved`가 붙었다. 헤더가 명시되지 않은 청크 49개, HTML 파서 보정 표시 2개도 남았다. 구조 오류를 발견했다고 기존 표 생성 결과를 덮어쓰지는 않았다. 48페이지 전체를 사람이 눈으로 검수한 것은 아니다.
