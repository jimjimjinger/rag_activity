# PM209 — 임베딩부터 검색·답변 평가까지

정리일: 2026-11-02 · 작업 범위: 2026-10-26 임베딩·DB 저장 ~ 2026-11-02 본문 질문 평가

**현재 상태:** 전체 126,938개 청크의 임베딩과 Qdrant 저장을 완료했고, 검색 근거를 받아 한국어로 답하는 LLM까지 연결했다. 이후 영어 질의 번역, 키워드 가중치, Top-1/Top-5를 같은 30문항으로 비교했다. 본문 분류 10문항도 별도로 집계했다. 서비스 화면·실제 이미지 표시와 전체 품질 검증은 아직 남아 있다.

## 1. 전체 구성과 역할

```text
기존 본문 OCR + 그림 description + 표 HTML
→ 청킹(기본 500자, 원본 위치 연결)
→ Qwen3-Embedding으로 벡터 생성
→ Qdrant에 벡터·청크·출처 저장
→ 질문으로 근거 검색
→ Qwen3.5-4B가 한국어 답변 생성
→ 근거 ID·출력 형식 확인 및 결과 저장
```

| 구성요소 | 역할 |
|---|---|
| 청킹 코드 | 본문·그림 설명·표 셀을 검색 가능한 텍스트 단위로 나누고 원본 ID·좌표를 연결 |
| Qwen3-Embedding-0.6B | 문서 청크와 검색 질문을 1,024차원 벡터로 변환 |
| SQLite 캐시 | 만들어 둔 임베딩을 보관해 재실행 시 재사용 |
| Qdrant | 벡터와 청크·출처 정보를 저장하고 코사인 유사도로 검색 |
| SQLite FTS5 / BM25 | 실험에서 기존 청크의 키워드 검색 수행 |
| 가중 RRF | 의미 검색 순위와 키워드 검색 순위를 결합 |
| Qwen3.5-4B | 검색된 근거를 이용해 한국어 답변 생성 |

현재 PM209 실행 연결은 **직접 작성한 Python 코드와 Ollama HTTP 호출**이다. LangChain이 현재 전체 RAG 실행을 구성하는 방식은 아니다. 임베딩 모델과 답변 모델의 역할도 서로 다르다.

## 2. 임베딩·Qdrant 저장 — 완료

- 대상: **209개 매뉴얼·10,018페이지 → 126,938개 청크**. 그림 23,807개와 표 2,320개가 모두 연결됐다.
- 청킹: 기본 **500자**이며 500토큰이 아니다. 본문은 문장 경계를 우선하고 긴 문장은 구절·단어 경계에서 나눴다. 연속 본문은 최대 100자를 겹친다. 그림 설명은 그림별로, 표는 행·셀 기준으로 나눈다. 긴 표 문맥 26개는 예외 표시 후 보존했다.
- 임베딩: **`qwen3-embedding:0.6b` Q8_0**, 1,024차원, 배치 4·동시성 1·문맥 2,048·`truncate=false`. 입력 초과를 조용히 잘라 처리하지 않는다.
- 저장: **Qdrant 로컬 디스크 모드**, 코사인 유사도. 별도 DB 서버나 Docker 없이 Python 라이브러리로 사용한다.
- 실행 시간: 임베딩 약 **90.2분**, DB 저장 약 **15.2분**, 최종 검증 등을 포함해 **약 1시간 51분**. 새 벡터 112,067개와 캐시 14,871개를 사용했다.
- 결과: **126,938개 벡터 전부 저장, 실패 0개**. 전체 ID·payload·벡터 대조와 검색·매뉴얼 필터 검사를 통과했다. 원본·그림·표 데이터 9개 JSONL의 해시도 보존했다.
- 환경: Windows 11, RTX 5060 Laptop, VRAM 8,151MiB. 임베딩 때 관측한 VRAM 최대 약 1,016MiB, 온도 최대 67°C였다.

저장 검증은 데이터가 제대로 들어갔다는 확인이다. 실제 질문의 검색·답변 정확도가 높다는 뜻은 아니다. 이후 실험에서도 문서 임베딩을 다시 만들지 않았다.

## 3. 검색과 답변 LLM 연결 — 완료

현재 기본 `answer` 명령은 **선택한 매뉴얼 안에서 한국어 질문으로 의미 검색 → 상위 5개 청크 → 한국어 답변 하나**를 생성한다. 실험용 영어 번역·키워드 가중치는 기본 명령에 자동 반영하지 않았다.

| 항목 | 설정·동작 |
|---|---|
| 답변 모델 | 로컬 `qwen3.5:4b` Q4_K_M |
| 생성 설정 | 문맥 8,192, 출력 최대 1,024토큰, `think=false`, temperature 0, 요청 제한 300초 |
| GPU 운영 | 질문 임베딩 모델을 내린 뒤 답변 모델을 적재. 동시성 1 |
| 모델 입력 | 원래 한국어 질문 + 검색 청크의 텍스트·유형·검수 표시·근거 ID |
| 모델 출력 | `answer`, `source_ids`, `insufficient_evidence` |
| 검사 | JSON 형식·정상 종료·한국어·유효한 근거 ID 확인. 형식 실패는 한 번 재시도 |
| 저장 | 터미널 출력과 JSON 기록. 실패도 별도로 남김 |

**QA 정답은 검색 자료나 모델 입력에 넣지 않는다.** 정답은 평가할 때만 비교한다. 실제 이미지를 답변 모델에 넣는 방식도 아니다. 그림은 기존 description, 표는 HTML에서 만든 텍스트 청크를 사용한다. 인용한 그림의 JPG 경로·영역 ID·좌표는 연결했지만 화면에 이미지를 표시하는 UI는 아직 없다.

근거가 부족하면 확인하지 못했다고 답하게 했다. 형식을 통과해도 오역·조건 누락·잘못된 추론은 생길 수 있으므로 별도 의미 검수가 필요하다. 생성 시 관측 VRAM은 약 3.8GB였으며, 현재 로컬 Qdrant를 매번 여는 비용이 커 최초 CLI 응답은 수십 초가 걸리기도 했다. 향후 화면에서는 DB 연결 재사용을 검토해야 한다.

## 4. 평가 방법과 비교 조건

- 고정 표본: val의 **21개 매뉴얼, 30문항**. 본문·표·그림 관련 질문을 각 10개씩 선정했다.
- 같은 질문·매뉴얼 필터·모델·프롬프트·평가 기준으로 비교했다. 평가 기준은 원본과 대조한 기대 답변이며 Codex가 검수했다. 독립적인 사람 평가는 아니다.
- **Top-1/Top-5는 답변 개수가 아니라 답변에 넣는 근거 청크 수**다. 페이지 단위도 아니다. 두 조건 모두 답변은 하나다.
- 정답률은 **완전 정답 / 전체 문항 수**다. 부분정답·오답·미답변·출력 오류를 구분하고 모두 분모에 포함했다.
- 검색 영역 Hit@1은 첫 청크와 정답 주석 영역의 ID가 겹치는지 확인한다. 같은 표의 제목이나 일부만 찾아도 Hit가 될 수 있어 답변 정답률과 다르다.
- 같은 30문항으로 설정을 탐색했으므로 별도 검증 세트의 일반 성능이나 통계적 우위를 뜻하지 않는다.

### 영어 번역과 키워드 검색을 추가한 이유

한국어 질문과 영어 매뉴얼 사이의 표현 차이를 줄이기 위해 **질문만 영어로 번역해 검색**했다. 답변 생성에는 원래 한국어 질문을 유지했다. 이어서 제품명·버튼명·조건 등의 단어를 활용하는 BM25를 추가했다.

| Top-5 검색 조건 | 정답 / 30개 |
|---|---:|
| 기존 한국어 질문 + 의미 검색 | 17개 · 56.7% |
| 영어 번역 + 의미 검색 | 20개 · 66.7% |
| 같은 영어 번역 + 의미 50%·키워드 50% | 18개 · 60.0% |

키워드 비중은 0·25·50·75·100%로 비교했다. 의미/BM25 후보를 각 20개씩 확보하고 다음 가중 RRF로 순위를 합쳤다.

```text
점수 = (1-w)/(60 + 의미 검색 순위) + w/(60 + 키워드 검색 순위)
w = 키워드 비중, 순위는 1부터 시작, 후보가 없는 쪽의 기여는 0
```

이 비중은 **검색 순위를 합치는 비중**이다. 모델의 학습 가중치를 바꾸거나 임베딩을 재학습한 것이 아니며, 검색 결과 개수의 비율도 아니다. 가중치 비교의 **0%에도 영어 번역이 적용**된다.

## 5. 가중치·Top-1/Top-5 결과

| 키워드 / 의미 | 전체 30문항 Top-1 | 전체 30문항 Top-5 | 본문 10문항 Top-1 | 본문 10문항 Top-5 |
|---:|---:|---:|---:|---:|
| 0% / 100% | 15/30 · 50.0% | 20/30 · 66.7% | 8/10 · 80% | 9/10 · 90% |
| 25% / 75% | 14/30 · 46.7% | 17/30 · 56.7% | 8/10 · 80% | 9/10 · 90% |
| 50% / 50% | 14/30 · 46.7% | 18/30 · 60.0% | 8/10 · 80% | 9/10 · 90% |
| 75% / 25% | 12/30 · 40.0% | 15/30 · 50.0% | 7/10 · 70% | 8/10 · 80% |
| 100% / 0% | 11/30 · 36.7% | 13/30 · 43.3% | 6/10 · 60% | 8/10 · 80% |

- **전체 30문항:** 이번 표본에서는 영어 번역 + 의미 검색 100%가 가장 높았다. 모든 가중치에서 Top-5의 답변 정답 수가 Top-1보다 많았다.
- **본문 10문항:** 0·25·50%가 동률이다. Top-5의 나머지 한 문항은 0%에서 오답, 25·50%에서 부분정답이어서 오류 정도에는 차이가 있다. 본문만 보면 키워드 검색이 불리하다고 단정할 수 없다.
- 키워드 0%·Top-5를 유형별로 보면 **본문 9/10, 표 6/10, 그림 관련 5/10**이었다. 그림 관련 질문도 본문과 함께 풀 수 있으며, 순수 이미지 이해 능력만 평가한 것은 아니다.
- 키워드 0%의 검색 영역 Hit@1은 **23/30(76.7%)**였지만, 근거 한 개로 만든 답변 정답은 **15/30(50.0%)**였다. 영역 검색 성공과 필요한 내용 확보가 다를 수 있다.

Top-5의 0%·50%는 앞선 결과를 재사용하고 25%·75%·100%의 90개 답변을 새로 생성했다(약 2분 45초, 최종 형식 오류 2개). Top-1은 150개를 새로 생성했다(약 3분 3초, 최종 형식 오류 1개). 이 시간은 검수 시간을 제외한 실행 시간이며, 번역·문서 임베딩·DB 재검색을 반복하지 않은 조건이다. 본문 10문항 비교는 기존 답변 100개를 분리해 검수한 것으로 새 GPU 생성은 없다.

본문 분류에도 한계가 있다. 기존 분류를 유지한 **입력 전압 질문(TEXT08)은 실제 수치를 표 청크에서 가져왔다.** 검색 대상을 본문으로만 제한한 실험은 아니다. 또한 10문항에서는 한 개 차이가 10%포인트라 최적 설정을 확정하기에는 작다.

## 6. 확인한 문제와 해석

| 문제 | 확인한 사례 | 의미 |
|---|---|---|
| 제목과 실제 내용이 떨어짐 | 입력 전압의 1위는 항목 제목, 실제 수치는 다음 표 청크 | Top-1에서 영역을 맞혀도 답하지 못함 |
| 가중치 변경으로 필요한 근거가 밀림 | 키워드를 높이면 헤드셋 포트는 좋아지지만 구성품 표·조건별 삭제 절차가 밀림 | 키워드 비중을 높인다고 일괄 개선되지 않음 |
| 근거가 있어도 필수 조건 생략 | Timeshift의 1.5GB 조건을 찾고도 Top-5 답변에서 빠뜨림 | 검색 이후 답변 생성의 문제도 별도로 존재 |
| 오역·조건 혼동 | Lock을 잠금 해제로 번역, 권장 온도를 최소 온도로 표현, 보호 데이터와 프로그램용 128MB 혼동 | 의미·숫자·조건 검수가 필요 |
| 표·그림 추출 및 연결 한계 | 표 조건과 셀 분리, OCR에서 버튼 이름 누락, 그림 설명의 방향 정보 부족 | 검색 가중치만으로 해결하기 어려움 |
| 출력 형식 실패 | 근거 부족이라고 답하면서 근거 ID도 기입 | 오류로 기록하고 정답에서 제외; GPU 부족·토큰 잘림과 구분 |

정답 QA 자체의 오류도 확인했다. TEXT08의 공식 QA는 100–400VAC였지만 원본과 OCR은 100–240VAC여서 **평가값만 보정하고 원본은 유지**했다. Timeshift는 질문 범위가 넓은데 공식 정답이 1.5GB 조건으로 좁다는 점도 기록했다. 같은 입력에서도 출력 문구나 상태가 달라진 사례가 있어 가중치 효과와 생성 변동을 구분했다.
