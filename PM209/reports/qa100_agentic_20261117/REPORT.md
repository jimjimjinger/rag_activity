# PM209 기존 Qwen Agentic RAG: 동일 100문항 비교

2026-11-17 · LangGraph · 기존 임베딩/검색 결과 보존 · 원본 QA 기준

## 적용한 기능

- 기존 Qwen3.5:4b가 질문에 필요한 조건과 현재 근거를 보고 finish/search/read_parent/read_table 중 하나를 선택합니다.
- 실제 LangGraph 상태·조건부 간선으로 실행합니다. 추가 검색은 최대 2회, 전체 도구 실행은 최대 4회이며 같은 검색·같은 원문 읽기 반복을 제한합니다.
- 질문별 작업 공간에 출처 ID와 원문을 보관하고 Qwen이 최종 근거 ID를 고릅니다. 계획 문장은 답변 근거에 섞지 않습니다.
- 표 도구는 기존 표 영역에 연결된 전체 행 청크를 읽습니다. 이미지 픽셀 확인·재OCR·새 표 생성은 하지 않습니다. Dr-DCI 논문 전체 재현도 아닙니다.

## 동일하게 유지한 조건

- 같은 100문항(본문 34·표 33·그림 33), 매뉴얼 필터, 키워드 50%, Qwen 임베딩 126,938개, BGE 후보 20→Top5, 부모 문맥, 압축 모델·프롬프트, 최종 답변 모델·프롬프트.
- 최초 번역·검색·리랭킹·부모 확장·압축 결과를 그대로 재사용해 동일한 출발점을 만들었습니다. 추가 검색 질의만 새로 임베딩했습니다.
- 에이전트의 근거 선택 및 도구 호출이 비교 대상입니다. 새로 얻은 텍스트는 기존 압축 방식으로 처리하고, 이미 압축된 최초 근거는 중복 압축하지 않습니다.
- 최종 모델 입력과 출력 스키마가 완전히 같을 때만 이전 답변을 재사용합니다. 다른 입력은 같은 답변 프롬프트로 새로 생성합니다.
- QA 정답·정답 영역·평가 판정은 실행 입력에서 제외하고, 실행 후 기존 161개 필수 사실과 동일한 기준으로 Codex가 의미 검수했습니다.

현재 구현은 근거를 추가하는 기능뿐 아니라 기존 근거를 골라 제외하는 기능도 함께 비교했습니다. 따라서 개선을 재검색만의 효과로, 악화를 에이전트 방식 전체의 한계로 단정할 수 없습니다. 표 핵심 답변은 두 문항 늘었지만 표 엄격 통과율은 같고 전체 핵심 충족률은 낮아, 일반 답변의 기본 설정은 유지합니다. 다음 실험 후보는 최초 근거 보존을 전제로 한 추가 탐색과 최종 근거 누락 방지입니다. 이번 결과를 본 뒤 모델을 다시 돌리거나 프롬프트를 조정하지 않았습니다.

TEXT006의 스위치를 앞으로 미는 방향, FIGURE022의 조명 조건에 따른 자동 화이트 밸런스는 고정한 필수 사실의 명시 여부가 경계입니다. 두 답변을 넓게 인정하면 적용 후 핵심 충족률은 73%이며, 기존 74%보다 높아지지는 않습니다. 주 결과 71%와 문항별 판정은 그대로 보존합니다.

## 실행과 자원

- 도구를 사용한 질문: 32/100. 호출 내역: {"read_parent": 28, "search": 19, "read_table": 5}
- 추가 검색 횟수별 문항 수: {"0": 85, "1": 11, "2": 4}
- 계획/판단 호출 175회, 형식·행동 검증 실패 시도 40회, 기존 근거 유지 fallback 16회.
- 차단된 계획은 같은 원문 재읽기 23회, 같은 질의 재검색 16회, 검색 외 행동에 질의 필드 사용 1회입니다. 도구 실행 전 검증으로 차단했으며 전체 작업을 중단하지 않았습니다.
- 답변 새 생성 91개, 동일 입력 재사용 9개. 새 질의 임베딩 19개, 문서 임베딩 재생성 0개.
- 최종 상태는 답변 97개, 근거 부족 1개, 출력 형식 검증 실패 2개입니다. TABLE027은 근거 부족 표시와 인용 ID를 동시에 출력했고, TABLE030은 기존의 본문 출처 ID 형식 실패가 동일 입력 재사용으로 유지됐습니다. 두 실패는 정답으로 세지 않았습니다.
- 이번 실행 경과 시간 18.2분. 이 시간은 최초 검색 등의 캐시 재사용, 추가 도구·모델 전환·저장·보존 검사 비용을 포함하며 의미 검수 시간은 제외합니다.
- 기존 100문항은 단계별 처리 시간 합계 약 18.5분이었습니다. 이번 실행은 최초 단계를 재사용하므로 두 시간을 그대로 나눠 속도 향상/악화로 해석하지 않습니다. 실제 서비스의 최초 처리 비용은 별도로 더해집니다.
- GPU 모델은 순차 실행했습니다. GPU 표본은 summary.json과 각 결정·답변 파일에 기록하며 연속 측정 최고치는 아닙니다.

이번 실행 표본의 최대 GPU 전체 사용량은 3,840MiB, 최대 온도는 69°C입니다. 원본·이전 결과 등 보호 대상 3,078개 파일의 해시가 같았고 문서 임베딩 재생성과 DB 쓰기는 0회였습니다.

## 해석 범위

- 같은 100문항을 반복 사용하는 개발 비교입니다. 새 질문에 대한 독립 평가나 통계적 우월성 검증은 아닙니다.
- 에이전트가 finish를 선택했다는 것은 모델의 판단이며 정답 인증이 아닙니다. 추가 검색 없이 근거만 선택하는 질문도 포함합니다.
- 동일 모델이 계획과 답변을 수행하므로 잘못된 해석이 반복될 수 있습니다. 최종 채점은 Qwen 자기 채점이 아니라 기존 QA와 실제 입력·답변을 대조한 Codex 검수입니다.
- 이미지 직접 확인 기능은 이번에 넣지 않았으므로 그림 설명에서 누락된 위치·아이콘은 여전히 해결하지 못할 수 있습니다.

## 파일과 재현

- `protocol.json`: 고정 모델·프롬프트·도구 예산·라이브러리 버전.
- `decisions/`, `tools/`, `agent-states.json`: 실제 모델 판단, 재검색·원문 읽기 결과, 작업 공간.

- `judgments.json`, `graded-results.json`, `summary.json`, `review.html`: 문항별 근거·정답 대조와 전후 변화.
