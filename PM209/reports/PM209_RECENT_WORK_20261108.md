# 부모 문맥 연결과 답변 비교

실험일: 2026-11-08 · 후속 검토: 2026-11-09

## 진행 배경

기존 30문항 실험에서 키워드 검색을 함께 사용했을 때의 답변 정답률이 의미 검색만 사용했을 때보다 낮았습니다. 검색된 짧은 청크만으로는 표의 설명이나 설치 절차의 앞뒤 내용이 빠질 수 있다고 보고, 검색한 청크에 관련 문맥을 연결하는 방법을 적용했습니다.

## 적용한 방법

LangChain의 **ParentDocumentRetriever가 사용하는 부모·자식 검색 구조**를 참고했습니다. 작은 청크로 검색하고, 답변할 때는 그 청크가 속한 더 큰 문맥을 함께 제공하는 방식입니다. 실제 구현은 기존 Qdrant 검색을 유지하면서 LangChain 체인의 검색 단계 뒤에 부모 문맥 조회 단계를 직접 추가했습니다. 내장 ParentDocumentRetriever 클래스를 그대로 사용한 것은 아닙니다.

기존 500자 청크와 임베딩을 유지하고, 문서의 제목·좌표·원본 영역 ID를 이용해 다음 내용을 묶었습니다.

- 같은 페이지에서 **같은 소제목 아래에 있는 본문·표·그림**
- 같은 **표·도면 내부에 들어 있는 설명과 레이블**
- 한 제목 아래에서 **번호가 연속되는 설치 절차** — 양쪽 열로 나뉜 단계도 연결

연결이 불확실한 경우에는 같은 원본 영역의 청크만 묶었습니다. 검색 Top-5를 먼저 확보한 뒤 연결된 부모 문맥을 추가하고, 중복과 모델 입력 길이 제한을 적용했습니다. 이번 실험에서는 답변 근거가 평균 5개에서 약 13.4개로 늘었습니다.

## 비교 결과

같은 30문항과 기존 영어 번역·검색 Top-5를 고정하고, 키워드 0%와 50%에서 답변을 각각 다시 생성했습니다. 모델과 기존 프롬프트는 유지했습니다.

| 키워드 비중 | 부모 문맥 연결 전 | 연결 후 |
|---|---:|---:|
| 0% — 의미 검색만 사용 | 66.7% | **73.3%** |
| 50% — 의미·키워드 검색 결합 | 60.0% | **66.7%** |

표 질문 정답률은 0%에서 **60% → 80%**, 50%에서 **50% → 70%**로 올랐습니다. 구성품 표나 설치 후반 단계처럼 기존 청크에서 떨어져 있던 내용을 보완하는 데 효과가 있었습니다.

다만 키워드 0%가 더 높은 결과는 유지됐습니다. 두 조건 모두 충분한 답변 근거가 포함된 비율은 86.7%였지만, LLM이 조건을 누락하거나 주변 수치를 잘못 덧붙여 최종 답변 정답률이 달랐습니다. 따라서 키워드 검색 자체의 문제와 답변 생성 오류를 구분할 필요가 있습니다.

## 추가 프롬프트 실험과 현재 상태

이후 질문에 필요한 내용만 답하고 수치·조건을 보존하도록 프롬프트를 수정했습니다. 이번에는 부모 문맥의 내용과 순서까지 고정했지만, 정답률은 0%에서 **73.3% → 70.0%**, 50%에서 **66.7% → 63.3%**로 개선되지 않았습니다.

현재는 **부모 문맥 연결을 적용하고 기존 답변 프롬프트를 유지**했습니다. 이번 30문항에서 가장 높은 결과는 **부모 문맥 + 기존 프롬프트 + 키워드 0%**였습니다. 같은 개발 문항에 대한 Codex 검수 결과이므로, 다른 질문에서도 같은 효과가 나는지는 추가 평가가 필요합니다.

## 다음 실험: 리랭킹 검토

2026-11-09에는 검색 후보 20개를 리랭커로 다시 평가해 상위 5개를 선택한 뒤, 부모 문맥과 기존 답변 프롬프트를 적용하는 방식을 검토했습니다. 키워드 0%·50% 각각에서 리랭킹 적용 전후의 정답 근거 포함률(Top-1/5), 최종 답변 정답률, 처리 시간을 구분해 비교할 계획입니다.
