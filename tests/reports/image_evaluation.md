# Structure와 VL 화면 캡처 정량 평가

평가일: 2026-10-15. 경량 Structure는 지민의 요청에 따라 제외했다. 저장된 8GB GPU 결과만 읽었으며 모델 재실행·추가 OCR·LLM 평가·RAG 재빌드는 하지 않았다.

## 결론

선택한 7개 캡처에서 추출 이미지 파일로 보존한 수는 Structure 6/7, VL 4/7이다. 캡처 안의 지정 문자열 35개 중 JSON 보존은 Structure 9/35, VL 6/35이며, 최종 Markdown 텍스트로 전달된 수는 Structure 1/35, VL 6/35이다.

**캡처를 이미지로 보존하는 성과와 내부 정보를 텍스트로 전달하는 성과가 달랐다.** 현재 VL은 image 영역의 OCR을 비활성화했으므로 이 수치를 VL 모델 자체의 이미지 이해 정확도로 해석하지 않는다. 본문·정형 표의 결과와 합쳐 단일 정확도로 평균 내지 않는다.

## 평가 대상과 정답 작성

원본 PDF를 CPU에서 페이지 폭 1,600px로 렌더링하고, 선택한 캡처를 3,600px 페이지 렌더에서 확대해 직접 확인했다. 6페이지의 캡처 7개에 대해 판독 가능한 문자열을 5개씩 전사했다. 20페이지 노란 메모에 가려진 항목, 로고·번호 원형·워터마크는 평가 항목에서 제외했다. 37~39페이지 정형 표 셀은 이 평가에 포함하지 않는다. 캡처 속 표의 지정 문자열은 여기에서만 집계한다.

**이미 출력을 살펴본 뒤 만든 회고적 진단 표본이다.** 무작위 표본이나 전체 이미지 정답지가 아니며, 사전 등록·블라인드 테스트 또는 독립 검증 세트로 주장하지 않는다. 문자열 35개는 해당 캡처의 전체 내용이 아니다.

## 1. 추출 이미지 보존과 Markdown 연결

원본 캡처 범위를 1,200×675 출력 좌표의 사각형으로 지정했다. 저장된 이미지 파일의 이름에 기록된 crop 좌표와 실제 픽셀 크기가 일치하는지 검사하고, 해당 이미지들이 덮는 원본 캡처 면적의 합집합을 계산했다. 분할·중복 이미지는 겹치는 면적을 중복 집계하지 않는다.

보존 기준은 원본 캡처 면적의 **95% 이상**이다. 이는 외곽 여백 차이를 허용하기 위해 정한 이번 실습의 기준이며 표준 벤치마크 임계값이 아니다. 보존으로 집계한 출력 이미지들도 직접 열어 원본과 대조했다. 픽셀 단위 화질 점수, 모든 작은 글자의 가독성, 중요 부분별 가중치는 측정하지 않았다.

- 파일 보존: 저장된 추출 이미지 전체를 대상으로 한다.
- Markdown 연결 보존: 최종 Markdown에서 실제 참조하는 추출 이미지들만 대상으로 한다.
- 원본 PDF 뷰어는 별도다. 추출 이미지 연결이 실패해도 Streamlit의 원본 PDF에서는 캡처를 볼 수 있다.

## 2. 캡처 내부 지정 문자열 보존

페이지 전체에서 단어를 찾지 않고, 캡처와 겹치는 parsing_res_list 블록만 사용했다. 블록 면적의 50% 이상 또는 캡처 면적의 50% 이상이 겹치면 해당 블록을 포함한다. Structure가 두 Jira 폼을 한 블록으로 합친 경우 그 블록이 두 캡처의 검사에 포함된다. 따라서 이 검사는 캡처 영역의 문자열 존재를 확인하며, 정확한 버튼 위치나 표의 행·열 귀속은 검증하지 않는다.

HTML 태그·대소문자·연속 공백·전각 문자·하이픈 형태를 정규화하고 지정 문자열을 정확히 비교했다. 문자열 내부의 철자·숫자·밑줄·구두점은 보존한다. 텍스트는 단어 경계를 확인한다. 날짜·숫자는 숫자 경계를 확인하므로 2631이 585263114033처럼 붙은 숫자열 안에 있으면 통과시키지 않는다.

JSON 보존율 = 지정 문자열이 캡처 블록 내용에 있는 수 / 35. Markdown 텍스트 보존율 = 해당 블록 내용이 Markdown 텍스트에도 포함되고 지정 문자열이 남은 수 / 35. 이미지 링크·파일 속 눈으로 읽을 수 있는 글자·오른쪽 기능 설명에 반복된 단어만으로는 통과시키지 않는다.

불일치는 **오인식 또는 미출력**을 뜻한다. 이를 모두 인식 오류나 환각으로 세지 않는다. 캡처 전체 문자 오류율, 출력 전체의 환각률, 필드-값 연결 정확도, 표 구조 TEDS, 이미지 의미 설명은 평가하지 않았다.

## 해석과 실제 오류 사례

- Structure 9페이지는 캡처의 지정 문자열 5개를 JSON에 남겼지만 Markdown에는 이미지 링크로 전달했다. 텍스트 전용 RAG는 이 이미지 속 글자를 읽지 않는다.
- Structure 31페이지의 완전한 캡처 파일은 저장돼 있지만 Markdown에서 참조하지 않는다. 이미지 파일 보존과 RAG 화면에 연결된 이미지 보존이 다른 사례다.
- VL JSON의 use_ocr_for_image_block=False를 확인했다. 9·14·20페이지의 image 블록은 캡처를 보존하지만 내부 OCR 텍스트를 출력하지 않아 지정 문자열 점수는 0이다. 이 설정을 켜서 재실행한 실험은 수행하지 않았다.
- VL 22페이지는 Title Length와 상·하한 조건을 텍스트로 전달했지만, Raw Data의 title_tag·title_len을 [1514-549, 1514-149]로 잘못 출력했다.
- VL 23페이지의 원본 날짜 2026-09-01은 2020-08-01로, 31페이지에서는 여러 날짜가 2020-00-01로 출력됐다. 표 헤더도 손상됐다. 많은 표 텍스트를 생성해도 지정 문자열 보존이 높다는 뜻은 아니다.
- 일부 날짜나 버튼 단어가 캡처 어디에든 존재하면 문자열 보존 검사는 통과할 수 있다. 예를 들어 14페이지 Create는 버튼 위치까지 확인하는 지표가 아니다.

## 비교 조건과 다음 평가

두 저장 결과는 같은 PDF, 페이지 폭 1,200px, 배치 1의 8GB 설정이다. 레이아웃 분류·이미지 OCR 정책·출력 방식은 다르므로 현재 파이프라인 구성의 비교다. 모델 자체의 캡처 OCR 능력을 비교하려면 같은 캡처 영역·입력 조건·출력 과제를 고정한 별도 실험이 필요하다.

## 재현

저장소 루트 PowerShell에서 실행한다. 기존 .venv의 Python과 Pillow만 사용하며 GPU 모델을 로드하지 않는다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -B .\tests\scripts\evaluate_images.py
```
